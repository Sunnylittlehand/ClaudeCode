## [Claude Code v2.1.296 — Workflow Subagent Model Pinning, Per-Subagent Context Compaction](https://code.claude.com/docs/en/changelog)
**Source**: Anthropic
**Type**: Product Update
**Date**: 2026-10-09
**Links**: [Official changelog](https://code.claude.com/docs/en/changelog) · [Dev Classmethod](https://dev.classmethod.jp/en/articles/20261010-cc-updates-v2-1-296/) · [Releasebot](https://releasebot.io/updates/anthropic/claude-code)

### Speaker / Author
Anthropic Engineering. Release follows v2.1.293–295 (covered 2026-10-12) and extends workflow-level governance controls for multi-agent sessions.

### Significance Rating
⭐⭐⭐☆☆ — Meaningful workflow governance additions for teams running multi-model agentic pipelines; operationally useful for cost control and compliance.

### 摘要
Claude Code v2.1.296（10 月 9 日）新增 CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL 环境变量，允许将工作流中所有子智能体固定为统一模型，非工作流子智能体则保持各自配置；autoCompactWindow 支持在子智能体前沿新增配置，可在主会话达到压缩阈值前触发压缩；CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS 可控制 529 超载请求的最大退避延迟。

### Summary
Claude Code v2.1.296 adds three operational controls: `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL` pins every subagent in a Workflow to a single model (non-workflow subagents retain their individual configuration); `autoCompactWindow` in subagent frontmatter or `--agents` definitions triggers context compaction before the parent session hits its own window, preventing cascading memory pressure; `CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS` sets a longer ceiling on backoff delays when retrying API overload (529) errors. Together these give ops teams fine-grained control over model spend and memory behaviour in complex multi-agent runs.

### Main Takeaway
Enterprise teams can now pin entire Workflow subagent fleets to a single model — critical for cost governance and audit consistency in regulated deployments.

### Relevance to Sunny
⭐⭐⭐☆☆ — The workflow model pin is operationally important for Sunny's rollout: it enables her platform team to lock all agentic workflow subagents to a specific approved model tier (e.g. Haiku 5.5 for cost-controlled tasks, Sonnet 5.5 for production), ensuring that model selection is a governance decision, not a per-developer override. This directly supports FCA model-governance obligations and cost-control frameworks. Pair with `deniedModels` (v2.1.283) for a complete model-restriction architecture.
