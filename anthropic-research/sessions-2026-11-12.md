## [Depi Security Research: Codex GitHub Actions Pipeline Backdoored via Prompt Injection — Full PoC Compromising OpenAI's npm Publishing Credentials](https://depi.security/blog/20261111-backdooring-codex/)
**Source**: Depi Security Research
**Type**: Security Research / Responsible Disclosure
**Date**: 2026-11-11
**Links**: [Depi PoC disclosure](https://depi.security/blog/20261111-backdooring-codex/) · [The Defiant](https://thedefiant.io/frontier/ai/researchers-say-codex-flaw-put-npm-releases-at-risk) · [GitHub issue summary](https://github.com/briiirussell/cybersecurity-skills/issues/266) · [SecurityIntel](https://buttondown.com/SecurityIntel/archive/securityintel-21-sep-openai-codex-sandbox-escapes/)

### Speaker / Author
Depi Security Research, an AI-security firm. Depi disclosed through Bugcrowd (OpenAI's bug bounty programme). OpenAI confirmed the fix. Depi previously appeared in OpenAI's security ecosystem; this is their most significant public Codex disclosure to date.

### Significance Rating
⭐⭐⭐⭐ Demonstrates a fully weaponised, end-to-end attack chain against an AI coding tool's supply chain — from a crafted GitHub issue through to takeover of the official npm publishing pipeline for Codex itself.

### 摘要
安全研究公司 Depi 于 11 月 11 日披露了一条针对 OpenAI Codex 的完整供应链攻击链：通过 GitHub Issue 触发提示注入 → 沙箱逃逸读取 Runner Token → 缓存投毒修改 CI/CD → 最终获得 Codex 官方 npm 包发布权限。攻击链已通过 Bugcrowd 负责任披露，OpenAI 已修复，未有恶意版本发布。此漏洞与 10 月 29 日 Cursor 扩展市场供应链攻击性质相似，表明 AI 编程工具的 CI/CD 流水线已成为攻击重点。

### Summary
Depi researchers disclosed a chained proof-of-concept attack that could have enabled a malicious actor to publish arbitrary code to OpenAI's official Codex npm package. The attack chain: (1) a crafted GitHub issue triggers a Codex prompt injection in the issue-labeller workflow; (2) a sandbox escape (exploiting .NET CLR debug pipes to read runner process memory) leaks `ACTIONS_RUNTIME_TOKEN`; (3) GitHub Actions cache poisoning modifies the CI/CD pipeline; (4) the attacker gains control of the npm publish step for the official `codex` package. No malicious npm release occurred, OpenAI confirmed it fixed the issue, and no CVE has been assigned. The researchers reported through Bugcrowd. This is conceptually similar in attack class to the October 29 Cursor extension marketplace trojan (already captured), which delivered an SSH backdoor to ~5,000 developer machines.

### Main Takeaway
AI coding tools' CI/CD pipelines have become a primary attack surface: within two weeks, researchers have demonstrated full supply-chain compromises against both Codex (GitHub Actions → npm) and Claude Code (Cursor extension marketplace → SSH backdoor).

### Relevance to Sunny
⭐⭐⭐⭐⭐ Critical for Sunny's enterprise risk posture. Two independent supply-chain attacks on AI coding tools in two weeks — one against Claude Code (Oct 29, already in ledger), one now against Codex's own build pipeline — establish a pattern that CISO teams and risk committees will need to address in vendor due diligence. For Sunny's bank, this reinforces the need for: (a) pin-to-verified-versions policies for all AI tool packages; (b) a CI/CD integrity review for any pipeline where AI coding tools generate or commit code; (c) inclusion of AI tool supply-chain risk in existing software supply-chain governance (e.g. NCSC Supply Chain Security guidance for UK financial institutions).
