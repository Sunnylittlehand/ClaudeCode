## [Claude Code v2.1.224 (Week 38): Self-Hosted Environments, Cross-Session Messaging, and Sandbox Hardening](https://code.claude.com/docs/en/changelog)
**Source**: Anthropic
**Type**: Product Update / Changelog
**Date**: 2026-08-07
**Links**: [Changelog](https://code.claude.com/docs/en/changelog) · [Blog: Run Sessions on Your Own Compute](https://claude.com/blog/run-claude-code-sessions-on-your-own-compute) · [Docs: Self-Hosted Environments](https://code.claude.com/docs/en/self-hosted-environments)

### Speaker / Author
Anthropic Engineering. The self-hosted environments feature is Anthropic's response to regulated-enterprise requests for agent compute that runs inside the customer's own network perimeter, extending a run of enterprise security moves in the first week of August (Inference Hooks, Chip Team, Volta compute deal).

### Significance Rating
⭐⭐⭐⭐⭐ — The first Claude Code release to route agent execution off Anthropic's cloud onto customer-controlled infrastructure; a direct blocker-remover for regulated deployments.

### 摘要
Claude Code v2.1.224 推出公测版"自托管环境"：企业可将 Claude Code 会话部署到自有服务器，支持固定运行器（分配型）与按需运行器（弹性型）两种模式，适用于 Team 与 Enterprise 计划。会话推理仍经由 api.anthropic.com 处理，但工具执行、代码检出与构建产物完全留在客户基础设施内，有效满足数据本地化合规要求。同版本还新增跨会话消息传递、HTTPS 压缩包插件安装（支持 SHA-256 固定）、移除每会话 200 子智能体上限，并修复多项沙箱安全漏洞。

### Summary
Claude Code v2.1.224 ships a public beta of self-hosted environments, letting Team and Enterprise organisations deploy a `claude self-hosted-runner` process so that web, mobile, desktop, and scheduled sessions run inside their own network rather than on Anthropic's cloud. Two runner modes are available: **fixed** (a set number of long-lived runners, sessions distributed across them) and **on-demand** (an orchestrator starts runners when sessions arrive and stops them when work finishes, so capacity tracks demand). Critically, **model inference still routes to `api.anthropic.com`** — only tool execution, filesystem access, repository checkouts, and build artefacts stay on customer-controlled infrastructure; this is execution-plane data residency, not full data residency. The same release adds cross-session messaging (`SendMessage`/`ListAgents` across machines on macOS and Linux), archive plugin installation from HTTPS zip files with optional SHA-256 pinning (no git or npm required), enhanced sandbox credential masking including JWT-aware masking and AWS SigV4-aware re-signing, removes the 200-subagent-per-session spawn cap, and fixes a Linux/macOS sandbox deny-rule trailing-slash bypass vulnerability.

### Main Takeaway
Claude Code now runs agent compute inside your network — not Anthropic's cloud — opening a credible deployment path for banks whose toolchain and data cannot leave the corporate perimeter.

### Relevance to Sunny
⭐⭐⭐⭐⭐ — This is the most practically significant Claude Code enterprise release since Inference Hooks (August 5). The FCA/PRA third-party risk concern with Claude Code has always had two layers: (1) model inference leaving the perimeter and (2) tool execution, code access, and repo checkouts leaving the perimeter. Self-hosted environments resolves layer 2. Layer 1 remains — inference still calls `api.anthropic.com` — but the data-residency story is now materially stronger: code, credentials, build artefacts, and the execution environment stay inside the bank's network. The security fix to the sandbox trailing-slash deny bypass (Linux/macOS) is also mandatory to apply. Sunny should use this to re-open conversations with security and legal teams who blocked Claude Code on data-locality grounds, framing it as execution-plane residency, and pair it with Inference Hooks (DLP on every prompt, August 5) and the Apps Gateway (inference plane stays in Bedrock/GCP, July 7) for a layered defence-in-depth presentation. Requires a developer/platform team to own runner setup and maintenance.

## [Sign in with ChatGPT: OpenAI Launches Cross-Platform Identity Provider on EU AI Act Enforcement Day](https://openai.com/index/sign-in-with-chatgpt/)
**Source**: OpenAI
**Type**: Product Launch
**Date**: 2026-08-02
**Links**: [TechTimes](https://www.techtimes.com/articles/322791/20260803/sign-chatgpt-launches-what-openai-retains-not-what-gets-shared.htm) · [OpenAI Security & Privacy](https://openai.com/security-and-privacy/)

### Speaker / Author
OpenAI Editorial. This is a strategic platform move, not a product update — OpenAI is inserting itself into the identity layer across the web, positioning it alongside Google, Apple, and Microsoft as a universal sign-in provider.

### Significance Rating
⭐⭐⭐⭐ — OpenAI's first cross-platform identity system; launched the same day EU AI Act enforcement and fining powers went live, with asymmetric data-retention implications that enterprise admins must address immediately.

### 摘要
OpenAI 于 8 月 2 日推出"Sign in with ChatGPT"公测版，以 OAuth 2.0 + OpenID Connect 为基础，成为跨平台身份提供商，首批合作伙伴包括 Airtable、GitLab、HubSpot、Notion、Supabase 和 Vercel。合作平台获取用户姓名、邮箱及头像，而 OpenAI 自身则保留 IP 地址、设备信息及每一个授权应用记录——披露范围远超共享范围。企业管理员若未主动禁用，默认处于开启状态。恰逢欧盟 AI 法案执行权生效同日，GDPR 合规风险值得关注。

### Summary
On August 2, 2026 — the same day the EU AI Act's enforcement and fining powers became active — OpenAI launched "Sign in with ChatGPT" in beta, built on OAuth 2.0 / OpenID Connect. Six launch partners are live: Airtable, GitLab, HubSpot, Notion, Supabase, and Vercel; additional plugins in ChatGPT's plugin directory can now use the same flow. When a user authenticates via this system, the **partner app receives** name, email, and profile picture. What **OpenAI retains** is materially broader: IP addresses, device details, and a full log of every application the user authenticates to via OpenAI's identity service. Enterprise global admins have two controls: disable Sign in with ChatGPT org-wide, or restrict it to an approved allowlist. Organisations without an explicit policy are **opted in by default**.

### Main Takeaway
OpenAI is now a digital identity provider — and enterprise bank admins who have not actively opted out are already sharing employee authentication events with OpenAI's identity logs.

### Relevance to Sunny
⭐⭐⭐⭐ — Two direct actions required: (1) check whether any bank employees already use ChatGPT Work with personal or enterprise accounts, and whether any partner apps (HubSpot, Notion, GitLab, Supabase) have been connected to ChatGPT via the plugin directory — if so, authentication events are now flowing to OpenAI's identity logs unless an admin has disabled this; (2) the default-opt-in posture is an FCA data-minimisation concern (UK GDPR Article 5(1)(c)) — regulated banks should add "Sign in with ChatGPT policy" to their ChatGPT Enterprise admin checklist and set an explicit restrictive policy. The timing alongside EU AI Act enforcement activation suggests this will receive scrutiny from data protection authorities.

### Summary
Released August 6, OpenAI's first country-by-country global usage report analyses over 800,000 messages from US ChatGPT users and broader geo data. The key workforce finding: **16.8% of work-related messages** and **43.5% of occupation-specific messages** involve tasks typically associated with a *different* occupation — quantifying how AI is blurring professional boundaries and enabling workers to operate outside their credentialed domain. Fastest per-capita growth in Q2 2026 was in Peru, Uruguay, and Costa Rica; Latin America, Oceania, and Africa are closing the gap with North America and Europe. Multimedia use reached 7.8% of messages following ChatGPT Images 2.0 (April 2026), up consistently year-to-date. The report doubles as IPO narrative material, showing ChatGPT's transformation from "asking" (information-seeking) to "doing" (task completion).

### Main Takeaway
AI is already dissolving occupational boundaries at scale: nearly half of all occupation-specific ChatGPT messages are about someone else's job — exactly the change-management dynamic Sunny needs to anticipate as Claude Code reaches non-engineer teams at the bank.

No single release covers the full stack, but the combined picture is the strongest regulated-deployment case Claude Code has had.
- **OpenAI is building an identity and distribution layer around ChatGPT.** Sign in with ChatGPT (Aug 2), Agent Plugins Open Standard (Aug 6), and ChatGPT Voice in Work/Codex (Aug 6) are all moves to make OpenAI a platform businesses build on rather than just a product they use. Regulated banks that have allowed ChatGPT access for employees need to review new default-on settings (identity, voice, Agent Plugins) rather than assuming their initial enterprise configuration still holds.
- **The competitive gap in auto-review is widening.** Codex's always-on auto-review (now ~$0.013/PR after the Luna upgrade) runs automatically at scale with no human trigger. Claude Code's /code-review requires explicit invocation. For bank SecDevOps teams evaluating both tools, this difference in automation depth is now a named capability gap.

Once filed, vendor dependency and financial stability questions will move from analyst discussion to formal board-level due diligence, and Sunny's internal stakeholders will face those questions.
