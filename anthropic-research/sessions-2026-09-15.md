### 摘要
Manifold Security披露了一个被命名为"GitSpawn"的漏洞类别，影响包括Claude Code和OpenAI Codex在内的七款AI编程工具。攻击者可在代码仓库的`.git/config`文件中注入`core.fsmonitor`钩子命令——当AI代理执行`git status`或`git diff`等常规Git操作时，该命令会在沙箱之外、无需用户授权的情况下静默执行。Claude Code在接受工作区信任提示之前即会触发该载荷；截至9月1日测试时，仍有四个漏洞未被修复（涉及Hermes Agent、Qwen Code、Grok Build及Claude Code的第二条攻击路径）。企业安全团队应立即审查开发者克隆的代码仓库来源策略。

### Summary
Manifold Security's "GitSpawn" disclosure reveals that a single line in a repository's `.git/config` file can make seven AI coding agents — including Claude Code and Codex — silently execute attacker-supplied code outside the sandbox, without any approval prompt. The attack abuses `core.fsmonitor`, a legitimate Git feature Git reads from the repository config when any AI agent runs `git status` or `git diff`. On Claude Code, the payload fires before the workspace-trust prompt is accepted; OpenAI separately published three CVEs the same day, covering the identical flaw class in Codex. Fixes had shipped for Claude Code (first path), Cursor, and Block's Goose by publication, while four agents — including a second attack path in Claude Code — were still exploitable when Manifold retested on September 1. Enterprise teams should review policies on which public repositories developers are permitted to clone into agent sessions.

### Main Takeaway
A single untrusted repository cloned by an AI coding agent can silently execute attacker-controlled code on the developer's machine — sandbox is not sufficient protection if `.git/config` is not treated as untrusted input.
