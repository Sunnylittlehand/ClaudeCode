### Speaker / Author
Anthropic Engineering / Platform Team. This feature was quietly released on November 5, 2026 and appeared in releasebot's Claude Developer Platform feed; Anthropic has not published a dedicated blog post.

### Significance Rating
⭐⭐⭐⭐ — A direct network-layer control for API access that closes a material gap in Anthropic's enterprise security posture; highly relevant for financial-services and regulated-industry deployments.

### 摘要
Anthropic 在 Claude 控制台新增 IP 白名单（测试版），允许组织将 API 密钥访问权限限制在最多 1,000 个 IPv4/IPv6 范围内，覆盖 Messages、Batches、Files 及 Admin API，不在列表内的请求将返回 403 错误。这是针对直接 API 访问的网络层控制，对金融服务等受监管行业意义重大。

### Summary
Anthropic has launched a beta IP allowlist feature in the Claude Console that restricts API key usage to up to 1,000 IPv4 or IPv6 CIDR ranges, enforced across the Messages, Batches, Files, and Admin APIs. Requests from addresses outside the configured list receive a 403 error. This is distinct from the Enterprise web-app allowlist (which controls browser access to claude.ai): this feature governs programmatic API access and is configured in the Console under Identity and Access. It went live on November 5, 2026 and is currently in beta for all API-access organisations.

### Main Takeaway
Banks and regulated firms can now lock Claude API keys to their own network perimeters — a foundational control for SOC 2, ISO 27001, and FCA operational resilience requirements.

⭐⭐⭐⭐⭐ — Must-read: directly shapes rollout decisions. This is a significant security control for Sunny's Claude Code rollout in a regulated banking environment. By configuring IP allowlists, her team can enforce that Claude API calls from Claude Code and any CI/CD pipelines can only originate from approved corporate network ranges — preventing exfiltration via developer laptops on personal networks or compromised credentials used off-premises. This directly addresses the "network-level access control" question her CISO team will ask during governance review. Sunny should raise this feature with her Anthropic account team and confirm whether it covers Bedrock/Vertex/Foundry endpoints (the docs suggest it currently only covers direct API access; cloud provider deployments have separate controls).
