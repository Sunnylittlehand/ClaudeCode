**Type**: Open Standard / Product Launch
**Date**: 2026-08-06
**Links**: [Spec on GitHub](https://github.com/agentplugins/agent-plugins-spec) · [Official site](https://agent-plugins.org/) · [OpenAI Devs X post](https://x.com/OpenAIDevs/status/2085398373511918022) · [Google Developers Blog](https://developers.googleblog.com/agent-plugins-package-your-skills-tools-and-more/) · [The Next Web](https://thenextweb.com/news/openai-agent-plugins-open-standard-skills-mcp) · [9to5Mac](https://9to5mac.com/2026/08/06/gpt-5-turning-one-as-openai-shares-new-agent-plugins-standard/)

### Speaker / Author
OpenAI Developer Platform team, co-published with Amazon Web Services, Cursor, GitHub/Microsoft, and Vercel as Core Maintainers of a Technical Steering Committee. Google subsequently confirmed as an additional Core Maintainer. This represents the broadest cross-vendor AI developer standard launched to date — every major AI developer platform except Anthropic's Claude and DeepMind is represented.

### Significance Rating
⭐⭐⭐⭐⭐ — A cross-industry packaging format for AI agent capabilities that could define how enterprise tools integrate AI going forward, timed to GPT-5's one-year anniversary and potentially setting the ecosystem standard before Anthropic can respond.

### 摘要
OpenAI联合亚马逊、微软、谷歌、Cursor、Vercel于8月6日发布Agent Plugins开放标准v1.0.0——一种将MCP服务器与Agent技能打包成可分发插件的格式。ChatGPT、Codex、GitHub Copilot、VS Code、Cursor、Kiro均为首批兼容客户端。Anthropic未参与制定，但该标准在底层支持MCP协议，Claude使用者可能受到一定影响。

### Summary
OpenAI and partners launched Agent Plugins 1.0.0 on August 6, a vendor-neutral specification for bundling MCP servers and Agent Skills into portable, distributable plugin packages. The standard was co-developed by a Technical Steering Committee including Amazon, Cursor, GitHub/Microsoft, OpenAI, and Vercel, with Google joining as a Core Maintainer — making it the largest cross-vendor AI tooling consortium to date. Compatible clients at launch include ChatGPT, Codex, Cursor, GitHub Copilot, Kiro, and VS Code. The standard deliberately leaves marketplace policies, trust, sandboxing, and installation to individual clients, making it a portable packaging contract rather than a governance framework. Anthropic is not a co-author, but the specification *bundles* MCP servers — so existing MCP server investments are not obsolete, but Claude connectors lack a native Agent Plugins distribution path.

### Main Takeaway
OpenAI has declared a "build once, run anywhere" standard for AI agent capabilities — and every major AI developer tooling platform except Anthropic's is on the founding TSC.

## [Claude Code v2.1.223: Four Permission-Bypass Security Fixes and /teleport for Cloud Sessions](https://code.claude.com/docs/en/changelog)
**Source**: Anthropic
**Type**: Product Update / Security Release
**Date**: 2026-08-06
**Links**: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

### Speaker / Author
Anthropic Engineering. This is a security-focused patch release following Week 37 (v2.1.222), addressing four separate permission-bypass vulnerability classes in a single version.

### Significance Rating
⭐⭐⭐⭐ — Four distinct permission-bypass security fixes in a single release is unusually high density for a routine patch; the bypassPermissions org-policy override fix is directly relevant to enterprise governance.

### 摘要
Claude Code v2.1.223（8月6日）修复了四个权限绕过安全漏洞：Bash命令可隐藏自身部分内容、Unicode填充可欺骗批准对话框、工作流脚本可通过dynamic import()逃逸沙箱，以及bypassPermissions设置可无视组织级禁用策略。新增/teleport提示（用于将云会话切回本地继续）和子代理模型限制警告。共19项变更。

### Summary
Claude Code v2.1.223, released August 6, 2026, contains 19 changes including four security fixes: (1) a crafted Bash command could embed parts of itself in positions that hide them from the permission-check display; (2) tabs or invisible Unicode characters could hide content in the approval prompt dialog, preventing reviewers from seeing what they were approving; (3) workflow scripts could use JavaScript dynamic `import()` to execute code outside the workflow sandbox; (4) an agent definition that set `bypassPermissions: true` could override an organization policy that explicitly disabled bypass mode — a critical enterprise governance gap. New features include owner-wildcard entries (`owner/*`) for `strictKnownMarketplaces`/`blockedMarketplaces` managed settings, a warning when a workflow agent's requested sub-model is restricted and the parent model silently substitutes, and a `/teleport` hint in cloud sessions showing how to resume locally with `claude --teleport <session-id>`.

### Main Takeaway
Anthropic patched a governance bypass: an individual agent definition could previously override an org-level `bypassPermissions: false` policy — this is now fixed in v2.1.223.

### Relevance to Sunny
⭐⭐⭐⭐ — The `bypassPermissions` org-policy override fix (item 4) is directly material to her enterprise deployment: it means earlier Claude Code versions (before v2.1.223) had a gap where individual agent files could silently bypass enterprise-level permission restrictions even when the admin had explicitly disabled bypass mode. She should verify all bank deployments are on v2.1.223 or later, and add this to the audit log for her security review. The Unicode-hiding and Bash-hiding fixes are also relevant to insider threat and prompt-injection scenarios. Enterprise IT should treat this as a mandatory update.
