## [Claude Code v2.1.311–314 — Write Path Containment, Guardrail Trace, IdP Group Routing, Idle Compaction](https://code.claude.com/docs/en/changelog)
**Source**: Anthropic

**Links**: [Official Changelog](https://code.claude.com/docs/en/changelog)

### Speaker / Author
Anthropic Engineering Editorial. These are operational changelog entries from the Claude Code product team covering versions 2.1.311 through 2.1.314, the first Claude Code releases since v2.1.310 (October 23) which was fully covered in sessions-2026-10-26.md.

### Significance Rating
⭐⭐⭐⭐ — `permissions.blockWritesOutsideWorkingDirectories` is a structural containment control with direct relevance to enterprise security governance; guardrail trace and IdP group routing round out a strong enterprise release.

### 摘要
Claude Code v2.1.314（10月30日）新增关键安全特性：`permissions.blockWritesOutsideWorkingDirectories`强制限制写操作范围，防止越界写入；`guardrail_trace`记录Bedrock护栏触发器但不暴露匹配内容，满足合规日志需求；支持按IdP用户组路由Claude应用网关流量；超过20万token的空闲会话自动压缩。v2.1.312（10月27日）新增`oidc.user_id_claim`支持Microsoft Entra `oid`字段识别用户，并增加云端例行任务的算力级别选择器。

### Summary
Claude Code v2.1.314 (Oct 30) adds `permissions.blockWritesOutsideWorkingDirectories`, which enforces that Write, Edit, and NotebookEdit tools refuse any path outside the configured working directories in every permission mode — a hard containment boundary regardless of how permissive the session's other settings are. `guardrail_trace` for Bedrock upstreams logs which Bedrock guardrail filter fired without capturing the matched text, giving compliance teams an audit trail without retaining sensitive content. The new `groups` list on Claude apps gateway upstreams allows routing by IdP group membership, enabling granular access control for different developer teams. Idle compaction (200K+ token conversations that sit idle are auto-summarised) prevents runaway token spend in long-running cloud sessions. v2.1.312 (Oct 27) adds `oidc.user_id_claim` so the gateway can identify users by `oid` (Microsoft Entra ID) rather than `sub`, fixing a common enterprise SSO mismatch; also adds an effort level selector to the cloud routine model picker and click-to-send in fullscreen mode. 81 bug fixes in v2.1.314 include a critical fix: sessions no longer fail with "Invalid effort level" when an admin caps a model's effort — the agent now lowers effort and retries transparently.

### Main Takeaway
`blockWritesOutsideWorkingDirectories` turns the working-directory boundary into a hard security enforcement point — the most direct write-containment control Claude Code has shipped.

### Relevance to Sunny
⭐⭐⭐⭐ — `blockWritesOutsideWorkingDirectories` directly addresses a class of concern that Sunny's bank security teams will raise: "can Claude Code write files outside the repository it's working in?" The answer is now a configurable hard no, not just a best-effort default. She should include this in her security architecture documentation and test it during pilot rollout. The `guardrail_trace` feature is also audit-trail gold for a regulated environment: Bedrock customers get a log of which guardrail fired without the matched text landing in logs — exactly the balance a compliance team wants. `oidc.user_id_claim` with `oid` support will unblock any pilot teams running Microsoft Entra ID (standard in UK banking) who hit the `sub` vs `oid` mismatch. The Entra ID fix is worth a quick note to IT/Identity teams as a prerequisite unblock.
