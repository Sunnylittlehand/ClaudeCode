### Speaker / Author
AIR Security, an enterprise AI-agent security startup, authored the research. Researchers Or Nevo, Dor Granat, and Niv Hoffman discovered the flaw in May 2026 and coordinated responsible disclosure with all four affected vendors before publishing. This is the first cross-vendor AI plugin supply-chain attack publicly documented at production scale, making AIR a significant voice in the nascent field of AI agent security.

### Significance Rating
⭐⭐⭐⭐⭐ — A zero-click, unattended RCE that breaks the SHA-pinning security assumption underlying all current AI coding agent plugin ecosystems, with GitHub Copilot still unpatched and affecting millions of enterprise developers.

### 摘要
AIR安全研究团队披露"Plugin4Shell"漏洞：攻击者可通过替换恶意插件绕过SHA哈希验证，在无需用户点击或重新安装的情况下，对Claude Code、Codex、GitHub Copilot及Gemini CLI实现零点击远程代码执行。该漏洞影响插件所能访问的源代码、云凭证、SSH密钥及内部仓库。Anthropic已于2026年6月至7月在Claude Code中完成修补，OpenAI在Codex v0.146.0中修复，GitHub Copilot至今未发布补丁，Google则直接停用了Gemini CLI。

### Summary
AIR Security publicly disclosed Plugin4Shell on September 17–18: a zero-click RCE that bypasses SHA hash pinning in AI coding agent plugin systems by swapping a trusted plugin for a malicious one that auto-installs silently, without any user interaction. The vulnerability gives an attacker the same permissions as the developer running the agent — source code, cloud credentials, SSH keys, secrets, and internal repositories. Anthropic patched Claude Code under coordinated disclosure (shipped before public announcement), OpenAI patched Codex v0.146.0 (July 29), Microsoft has not shipped a fix for GitHub Copilot, and Google deprecated Gemini CLI rather than patching it.

### Main Takeaway
SHA-pinned AI agent plugins are not a trusted supply chain boundary — a malicious plugin update can silently execute attacker code in the developer's environment, and GitHub Copilot users remain exposed today.
