## [Claude Code v2.1.248: --restricted Flag for Hardened Environments, /usage-credits, and Cross-Cloud Session Messaging](https://code.claude.com/docs/en/changelog)
**Source**: Anthropic
**Type**: Product Update — Changelog
**Date**: 2026-08-27
**Links**: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

### Speaker / Author
Anthropic Engineering — Claude Code release team. v2.1.248 is notable primarily for two enterprise-facing additions: the `--restricted` execution flag and Enterprise-plan usage credit controls.

### Significance Rating
⭐⭐⭐⭐ — The `--restricted` flag is the first native execution sandbox built into Claude Code itself rather than relying on external container controls — directly relevant to bank developer environment governance.

### 摘要
Claude Code v2.1.248推出`--restricted`标志，在受限模式下移除所有命令执行工具及WebFetch，仅保留工作目录内的文件工具，并拒绝`bypassPermissions`——适用于企业高度管控环境（如CI/CD流水线、隔离沙盒）。新增`/usage-credits`命令供Enterprise组织申请更高使用限额，跨会话消息传递现已支持Amazon Bedrock、Google Vertex及Microsoft Foundry上托管的会话，并提供每代理提示缓存TTL可配置项。

### Summary
Claude Code v2.1.248 introduces a `--restricted` CLI flag that removes built-in command-execution tools (Bash, RunCode) and `WebFetch`, keeps file-system tools limited to the working directory, and blocks `bypassPermissions` — creating a sandboxed-by-default mode suited for CI/CD pipelines and regulated environments. It also adds `/usage-credits`, an Enterprise command to request higher usage limits without filing a support ticket; extends cross-session `SendMessage`/`ListAgents` to Claude instances running on Amazon Bedrock, Google Vertex, and Microsoft Azure Foundry; and adds `experimental.cacheTtl` for per-agent prompt-cache TTL configuration.

### Main Takeaway
Claude Code now has a native restricted mode that hard-removes execution tools — letting banks deploy Claude Code in governed CI environments without relying solely on configuration files or container controls.

### Relevance to Sunny
⭐⭐⭐⭐ — The `--restricted` flag is immediately actionable for Sunny's rollout. It means developer teams can run Claude Code in analysis-only mode inside the bank's CI/CD pipelines — Claude can read code, suggest fixes, and explain changes, but cannot execute arbitrary shell commands or make external web requests. This directly addresses the bank's likely control requirement that AI tools in SDLC pipelines must not have unrestricted execution access. Sunny should add this flag to the standard Claude Code CI configuration in the bank's internal setup guide and include it in the change-management training for developer teams.

Claude Code v2.1.247新增`SendFeedback`工具，当工具持续失败或操作出错时，Claude可自动起草反馈报告供用户审核后提交，可通过`feedbackDrafts`设置禁用。新增`/claude-api cost-optimize`命令，自动分析当前会话的Token支出并提出提示缓存、批处理、Token清理及模型选择优化建议。Admin API技能已更新，覆盖组织成员、邀请、工作区、API密钥、速率限制和CMEK配置。

The `/claude-api cost-optimize` command profiles the session's token spend and works through cost levers: prompt caching, request batching, token hygiene, and model selection. The Admin API skill is also updated to cover organisation members, invites, workspaces, API keys, rate limits, and CMEK configuration.

### Main Takeaway
Claude Code can now audit its own API spend and surface actionable cost-reduction suggestions — a practical tool for enterprise teams managing Claude Code budgets at rollout scale.
