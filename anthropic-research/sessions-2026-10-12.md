## [Claude Code v2.1.293–v2.1.295 — Haiku 5.5 Default, Instruction-Hook Fixes, Hooks Can Block on Failure](https://code.claude.com/docs/en/changelog)
**Source**: Anthropic
**Type**: Product Update / Changelog
**Date**: 2026-10-07 to 2026-10-09
**Links**: [Official Changelog](https://code.claude.com/docs/en/changelog) · [Havoptic v2.1.293](https://www.havoptic.com/r/claude-code-2.1.293) · [Havoptic v2.1.294](https://www.havoptic.com/r/claude-code-2.1.294) · [Havoptic v2.1.295](https://www.havoptic.com/r/claude-code-2.1.295)

### Speaker / Author
Anthropic Editorial — Claude Code engineering team. Previous batch (v2.1.290–292) was covered in sessions-2026-10-10.md.

### Significance Rating
⭐⭐⭐ — Three targeted releases: Haiku 5.5 becomes the default small model (75% cost reduction), instruction-based hooks are fixed to actually block what they were set to block, and hooks can now halt operations on failure — improving both cost efficiency and governance reliability.

### 摘要
Claude Code发布v2.1.293至v2.1.295：v2.1.293将Haiku 5.5设为默认小模型（成本降低约75%，具备百万上下文窗口）；v2.1.294修复指令式钩子无法正确阻断操作的回归缺陷；v2.1.295新增钩子失败时可阻断操作的能力及终端状态更新，提升企业治理可靠性。

### Summary
v2.1.293 (Oct 7) made Claude Haiku 5.5 the default small model in Claude Code — approximately 75% cheaper than Haiku 4.5 and carrying a 1M context window, which substantially reduces costs for large agentic workloads. v2.1.294 (Oct 8) fixed a regression in which instruction-based hooks were not blocking the actions they were configured to block, and made Stop/SubagentStop hooks more accurate so Claude is less likely to terminate prematurely. v2.1.295 (Oct 9) enabled hooks to block actions when they fail (previously a failed hook would not interrupt the action), and added terminal status updates and a "Backgrounding cancelled" message for clearer session-state feedback.

### Main Takeaway
The hook reliability fixes in v2.1.294–295 are the most governance-relevant changes: instruction-based hooks were silently failing to block, and failed hooks were not halting actions — both of which are security gaps in permission-enforcing deployments.

### Relevance to Sunny
⭐⭐⭐⭐ — Any Claude Code enterprise deployment using instruction-based hooks as a permission gate should treat versions below v2.1.294 as potentially unreliable — hooks were not blocking as configured. Sunny should confirm her deployment pipeline is on v2.1.294 or later before expanding rollout scope. The v2.1.295 "block on hook failure" change also reduces the risk of an action proceeding if a governance hook errors out unexpectedly.
